Patrol Grid Visit Workflow — User Guide

This guide walks you through loading, configuring, and running the Patrol Grid Visit Workflow, which maps how many distinct ranger patrols visited each cell of a grid laid over your patrolled area.

What it produces

  • An interactive map of grid cells colored by the number of distinct patrols that entered them (5 equal-interval bins, red–yellow–green)
  • A dashboard containing the map, the workflow details, and the analysis time range

Requirements

  • Access to an EarthRanger instance with a configured data source
  • Patrols in that instance with status done and recorded tracks in the analysis period

1. Load the Workflow

In the workflow runner, add a new template using this repository's URL:

https://github.com/wildlife-dynamics/patrol-grid-visit.git

Once added, select Patrol Grid Visit from the available templates list to load it.

2. Configure the Workflow

You'll be prompted to fill in the following parameters before running.

Relocations To Trajectory — Segment Filter (advanced)

Removes GPS noise and unrealistic movements when patrol track points are joined into segments.

FieldDefaultDescription
Min Length Meters0.001Discard segments shorter than this distance
Max Length Meters100000Discard segments longer than this distance (100 km)
Min Time Secs1Discard segments shorter than this duration
Max Time Secs172800Discard segments longer than this duration (48 hours)
Min Speed Kmhr0.01Discard segments below this average speed
Max Speed Kmhr500Discard segments above this average speed

Note: The defaults are permissive so that foot, vehicle, motorbike, and aerial patrols are all kept. The trade-off is that long straight lines across GPS gaps are kept too, and every cell they cross is counted as visited. For foot patrols, tighter limits (e.g. max 5000 m, 21600 s, 9 km/h) give a more faithful map.

Patrol Coverage Grid

FieldDefaultDescription
Grid Cell Size1000Edge length of each square grid cell, in meters. Smaller cells give a finer map but each cell gets fewer visits

3. Run the Workflow

Once all parameters are configured, submit the workflow. The runner will:

  1. Fetch the tracks of completed patrols from EarthRanger for the selected patrol types and time range.
  2. Join the track points into trajectory segments, dropping segments outside the segment filter limits.
  3. Build a square grid over the patrolled area and count the distinct patrols that entered each cell.
  4. Classify the counts into 5 equal-interval bins and color them red–yellow–green.
  5. Draw the interactive map and dashboard, and save outputs to the directory specified by ECOSCOPE_WORKFLOWS_RESULTS.

Output Files

All outputs are written to $ECOSCOPE_WORKFLOWS_RESULTS/:

Reading the map

  • Each cell's color shows how many different patrols entered it. A patrol that loops through a cell several times still counts once.
  • Only cells that at least one patrol entered are drawn. Blank areas were not patrolled in the period, or their tracks were removed by the segment filter.
  • Straight lines of low-visit cells running across otherwise empty areas usually come from a GPS gap: the segment joining the fixes on either side of the gap was kept by the filter. Tighten the segment filter to remove them.
  • Bins are equal-width ranges between the least- and most-visited cells, so one very busy cell (e.g. next to a ranger post) can push most other cells into the lowest bin.
